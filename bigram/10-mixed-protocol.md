# bigram · 10 混合题打分协议（可证伪）

## 结论 B10-1 先用 08 的 gap 表做硬过滤，再用 09 做微排序

```text
步骤1  查 B08-1 表得到 gap(opt,lr) ∈ [0, 0.5]
步骤2  若存在选项 gap≥0.20 且另一选项 gap≤0.10 → 直接淘汰差的（预测正确率目标 ≥90%）
步骤2b 若剩余选项 gap 都在优/良档且 |Δgap|≤0.05 → 【刀刃】禁止用 gap 决胜，
       必须走步骤3 的架构加减，或输出低置信（见 B08-1 规则4）
步骤3  若剩余选项 gap 都在 [0, 0.12]（优档）→ 用 B09-1 的 median 优势做加减
       （优档内部的 lr 档次（1e-3 vs 3e-3 vs 1e-2）不计分，视为同一好档）
步骤4  steps 联立 lr（B08-3）：lr≤3e-4 偏大 steps；lr=3e-3 偏小 steps
步骤5  总 CE 估计 = gap(opt,lr) + Σ arch_median_delta + steps_delta
       选 argmin
```

### 权重（可证伪）

| 项 | 量级来源 | 若用 |
|---|---|---|
| gap(opt,lr) | 0–0.50 | **主项** |
| width 一档 | +0.06–0.08 | B09-1 |
| dff 256→64 @w64 | +0.044 | B09-1 |
| heads（仅 dff=128 且 w≥64） | 0～+0.02 | 弱 |
| heads @dff=256 | **0** | 不计入 |
| steps @lr≤3e-4 | 1024−256 ≈ −0.14 | B08-3 |
| steps @lr=3e-3 | 1024−256 ≈ **+0.37** | B08-3 |

**可证伪预测**：

1. mixed 题中「一优档 + 一淘汰区」子集正确率 **≥90%**
2. 「全优档 + width 差一档」子集正确率 **≥75%**
3. 「全优档 + 仅 heads/depth 差」子集正确率 **≈50–65%**（预期刀刃）

## 适用范围

- **指标**：test CE / 选项命中（见正文）  
- bigram 100 题中的 optimizer_only / mixed
- 架构字段可从题面 materials 解析（d_model/num_layers/num_heads/d_ff）
- gap 表范围见 `08`；架构 median 见 `09`

## 边界

- 未建模：wd、mom 细节、GRU 的 n_params 对齐
- 两 w=128 包对打：**协议应输出“不确定”**，不要假装精确
- 不是官方 labeler；只服务知识自测

## B10-2 为什么 mixed 曾卡在 58%

旧规则把 heads/depth 与 gap **同权相加**，导致：

- 淘汰区选项被架构分追上
- dff=256 时 heads 误加分

B10-1 用 **gap 主项 + 仅在优档内比架构**，与 spiral 的「C02 先滤，再 C03」同构。
