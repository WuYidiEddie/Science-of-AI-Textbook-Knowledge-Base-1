# bigram · 07 架构细颗粒判断规则

面向 **选择题 / 配置选择** 的细粒度架构判断。  
指标：test CE（越低越好）。证据来自 `experiments/bigram/source` 的单因素配对与整包对打（E8 为主，E9/cliff 辅证）。  
分析脚本：`experiments/bigram/_analyze_arch_fine.py`，汇总 `_arch_fine_summary.json`。

> 与 `02-architecture.md` 的关系：02 是单因素主效应；**本文处理交互与整包**。  
> 与自测（`06`）的关系：自测证明「单因素 heads 直接相加」在题面上会错；本文给出条件化版本。

## 适用范围（全文默认，除非某条另写）

| 项 | 取值 |
|---|---|
| 任务 | bigram 语言模型，**test CE** |
| 证据 | `experiments/bigram/source` 的 E8 单因素配对 + 整包对打；E9/cliff 仅辅证 |
| 形状 | `kind/d/w/dff/heads`；TF 为主，GRU 样本少 |
| 典型网格 | w∈{32,64,128}，dff∈{64,128,256}，heads∈{2,4}，steps∈{256…2048}，bs∈{16,32} |
| 数据集 | V24a1 / V32a1 / V48a14（E8/E9） |

**范围外不保证**：w∉{32,64,128}、heads∈{1,8}、GQA、同 FLOPs 对照、超大模型/长序列、非 bigram 任务族。各小节另有「范围 / 范围外」收窄条件，以小节为准。

---

## 总判断顺序（在范围内按此优先级）

```text
1) 先定 width 档（32 / 64 / 128）——最大杠杆
2) 同 width 档内抬 dff（64 → 128 → 256）
3) 按 (width, dff) 定 heads（见 A-HEAD）
4) 再谈 depth（弱，且可双峰）
5) 最后才 TF vs GRU（看 lr/steps 语境）
```

禁止：把单因素胜率直接相加；在 dff 共变时套用「2 头一定好」。

---

## A-WIDTH 宽度档

### A-W1 更宽几乎总是更好（在 d 深度可比时）

| 对比 | 胜率 | Wilson 95% | 范围 |
|---|---:|---|---|
| 128 > 64 | 18/24 @d1 **75%**；21/24 @d3 **88%**；43/48 @d4 **90%** | 随深度升高 | E8，dff/heads 固定 |
| 64 > 32 | 36/48 @d3 **75%**；37/48 @d4 **77%** | | 同上 |

**范围**：E8，`w∈{32,64,128}`，同 `(ds,ctx,kind,d,dff,heads)`。  
**范围外**：w>128；参数量强约束；过拟合区。

### A-W2 「更深更窄」 vs 「更浅更宽」：优先更宽

在只比较 *depth 与 width 同时不同*（更深且更窄 vs 更浅且更宽）的 591 对里：

- **更宽者赢 471（79.7%）**，更深者赢 120

典型（同 ctx 对打）：

| 对打 | 结果 |
|---|---|
| `d1 w128 dff256 h2` vs `d3 w64 dff256 h4` | **宽 20 : 4**，宽侧平均优势 0.20 CE |
| `d3 w32 dff256 h4` vs `d1 w128 dff256 h2` | **宽 18 : 6** |

**范围**：E8 网格内出现过的 (d,w) 对；同语境。  
**含义**：宽度预算优先于深度预算。

### A-W3 窄宽度（w=32）的补偿包

w=32 的常胜整包是：

```text
(d=3, w=32, dff=256, heads=4)   —— 24 个语境里 17 次全场最佳
```

**范围**：E8，w=32 档，训练语境 12 种。  
**不要**写成「w=32 时 d 要 3」——只是该档赢家特征；换 dff/heads 后未测。

## A-DFF FFN 维度

### A-D1 同 (w,d,heads) 时，dff=256 强于 64/128

| 单元 | 最优 dff | 说明 |
|---|---|---|
| w64 d3 h2 | **256** 18/24 | |
| w64 d4 h2 | **256** 18/24 | |
| w64 d2 h4 | **256** 19/24 | |
| w128 d1 h2 | **256** 15/24 | 次优 128 |
| w128 d1 h4 | **256** 15/24 | 64 明显差 |

单因素全局：256>64 **73%**，256>128 **72%**，128>64 **70%**。

**范围**：dff∈{64,128,256}；E8 tf。  
**范围外**：dff≫256 或 dff≪w/2。

### A-D2 宽度越大，继续加大 dff 的收益越小

| 单元 | 256>128 胜率 | 256>64 胜率 |
|---|---:|---:|
| **w=64** | **79%**（55/70） | **76%**（73/96） |
| **w=128** | **62%**（29/47） | **63%**（15/24） |

**含义**：

- w=64：dff 256 明显值（相对 128/64）
- w=128：dff 128 往往已够；256 仅弱优势，且易与 heads/depth 绑成刀刃包

**范围**：同上；对打 hold `(ds,ctx,kind,d,heads)`。

### A-D3 大 dff 赢时优势小，小 dff 赢时优势大（不对称）

**适用范围**：E8，单因素 dff∈{64,256}，hold `(ds,ctx,kind,d,w,heads)`；3-seed CE。

全局 256>64：赢家平均优势 **0.058**；但 64>256 时平均优势 **0.26**。  
→ 小 dff 反超通常是 **训练不稳/语境不适配**，不是「小 FFN 更好」的常态。

**范围外**：不能推出「小 dff 更优」；仅解释反例幅度不对称。

## A-HEAD 注意力头数（必须带条件）

> **废止无条件版**「w≥64 时 2 头好」。改为下表。

### A-H1 条件表（单因素只改 heads，hold d,w,dff）

| 条件 | 2 头胜率 | 4 头胜率 | n | 建议 |
|---|---:|---:|---:|---|
| w=32（无论 dff） | **21%** | **79%** | 24 | **选 4 头** |
| w=64, dff=64 | **79%** | 21% | 24 | 选 2 头 |
| w=64, dff=128 | **95%** | 5% | 22 | **强选 2 头** |
| w=64, dff=256 | **68%** | 32% | 72 | 选 2 头，但可刀刃 |
| w=128, dff=128 | **89%** | 11% | 47 | **强选 2 头** |
| w=128, dff=256 | **75%** | 25% | 24 | 选 2 头 |
| dff=128（任意 w 有测） | **91%** | 9% | 69 | 强 2 头 |
| dff=256（任意 w） | **60%** | 40% | 120 | **近平局，勿写硬规则** |

**范围**：E8，heads∈{2,4}，w∈{32,64,128}，dff∈{64,128,256}。  
**范围外**：heads=1/8；GQA；w∉{32,64,128}。

### A-H2 整包中的 heads：与 d,dff 绑定时不要拆开比

**适用范围**：E8 同 ctx 整包对打；`d1 w128 dff256` 的 h2/h4 对，以及 w=128 档赢家统计（24 语境）。

对打（同 ctx）：

| 整包对比 | 结果 |
|---|---|
| `d1 w128 dff256 **h2**` vs 同但 **h4** | **h2 18 : 6**（优势 0.10） |
| 全场赢家特征 | w=128 档赢家常为 `d4 w128 dff128 **h4**`（10/24） |

→ **同 (d,w,dff) 只改 heads：按 A-H1。**  
→ **不同 (d,w,dff) 也改 heads：先比 width/dff 包，不要单独算 heads 分。**

## A-DEPTH 深度（弱且可双峰）

### A-DP1 全局「更深略好」仍成立，但弱

**适用范围**：E8，tf，d∈{1..4}，单因素只改 d，hold `(ds,ctx,w,dff,heads)`。

见 02：d3>d2 约 67%，d2>d1 约 63%，d4>d3 仅 58%。  
**范围外**：d>4；与 A-DP2 包内双峰并存时以 DP2 为准。

### A-DP2 包内深度常双峰，禁止写成单调

| 包 | 语境内最优 d | 形态 |
|---|---|---|
| w64 dff256 h2 | **d4 15 / d2 8** | 偏深 |
| w64 dff256 h4 | **d4 15 / d1 7** | 双峰 |
| w128 dff128 h4 | **d4 13 / d1 8** | **双峰** |
| w64 dff128 h4 | **d4 16 / d3 6** | 偏深 |
| w64 dff64 h2 | **d3 13 / d4 11** | 近平 |

对打：`d4 w64 dff256 h2` **16 : 8** 胜 `d2` 同包。

**范围**：E8 同 width/dff/heads 包内。  
**实务**：同 width/dff/heads 时可略偏 d=4；若对手是「极浅+超大 dff」不要自动判深胜（见 A-PKG）。

## A-GRU 何时考虑 GRU

### A-G1 匹配 (d=2,w=64) 对打 TF

| 语境 | GRU 胜率 | 说明 |
|---|---:|---|
| 全体 | 11/24 ≈ 46% | 无普适赢家 |
| **lr ≤ 3e-4** | 6/16 ≈ **38%** | 偏 TF |
| **lr ∈ {1e-3,3e-3}** | 5/8 ≈ **63%** | 偏 GRU |
| lr=mid 且 steps=512 | **4/4** | GRU 优势巨大（平均 ~0.79） |

不对称性：GRU 赢时平均优势 **0.32–0.63**；TF 赢时优势常 **&lt;0.1**。  
→ 题面若是「TF 优化好 vs GRU」，**低 lr 信 TF；中高 lr 或中预算信 GRU**。

**范围**：E8/E9 小形状，`d,w` 匹配但 **非同参数量**（GRU 无 FFN）。  
**范围外**：大模型、长序列、同 FLOPs 对照（未测）。

### A-G2 整包对打

| 对打 | 结果 |
|---|---|
| `tf d4 w64 dff256 h2` vs `gru d2 w64` | TF **16 : 8**，但 GRU 赢时 ~0.53 |
| `tf d4 w128 dff128 h4` vs `gru d2 w64` | TF **16 : 8** |

强 TF 整包可胜 GRU；**中等 TF 包 + 危险 lr** 时 GRU 反而稳。

## A-PKG 题面常见整包对打（E8 同 ctx）

| 名称 | 形状 (kind,d,w,dff,h) | 结果摘要 |
|---|---|---|
| 浅宽大FF | tf,1,128,256,2 | 与深宽均衡 **12:12**；赢时很大（~0.34），输时很小（~0.04）→ **高方差包** |
| 深宽均衡 | tf,4,128,128,4 | w=128 档常胜包（10/24） |
| 中窄大FF | tf,3,64,256,4 | 被浅宽大FF **20:4** 碾压（宽度优先） |
| 窄大FF | tf,3,32,256,4 | 输给浅宽 **6:18** |
| 深中FF | tf,4,64,256,2 | 胜同包 d2 **16:8** |

### A-PKG1 浅宽大FF（d=1,w=128,dff=256,h=2）使用条件

**适用范围**：E8 24 语境（V24/V48 × 12 ctx）整包对打；tf；非同参数量对照。

- **优于**更窄的中等模型（宽度效应）
- 与 `d=4,w=128,dff=128,h=4` **均势**，看语境：低 lr / 多步时更易成刀刃
- 同包选 heads：**h2 ≻ h4**（18:6）

**范围外**：不能写成全局最优包；与 GRU/更宽模型的对打见 A-G2 / A-W。

### A-PKG2 深宽均衡（d=4,w=128,dff=128,h=4）

**适用范围**：E8 24 语境 w=128 档赢家统计与整包对打；tf。

- w=128 档最高频赢家
- 在需要「稳」时优于浅宽大FF 的高方差包
- heads=4 在此包是特征，**不可**外推为「4 头更好」

## A-DECISION 可执行决策清单（范围内）

假设只能看题面超参，CE 更低者胜：

1. **width 不同** → 选更大的（A-W1/A-W2）  
   *除非* 宽模型伴随明显更差的训练语境（大 lr+短步）——那是 OPT/BUD 域，先比语境。
2. **width 同，dff 不同**  
   - w=64：选 dff=256（A-D2）  
   - w=128：dff=128≈256 皆可，略偏 256；**不要**为 dff 256 放弃 width
3. **width+dff 同，heads 不同** → 用 A-H1 条件表（w=32 选 4；其余选 2；dff=256 时勿写满置信）
4. **heads 与 dff 一起变** → 先比 (w,dff) 包，忽略单独 heads 分
5. **depth 不同且 width 同** → 略偏深（d=4 或 d=3），但接受双峰（A-DP2）
6. **TF vs GRU** → 低 lr（≤3e-4）偏 TF；lr 1e-3–3e-3 或 steps≈512 偏 GRU（A-G1）
7. **margin 估算**：同包 heads 差 ~0.01–0.10；width 差 ~0.08–0.16；dff 差 ~0.03–0.06；depth 差 ~0.01–0.04  
   → 分差 &lt;0.05 按刀刃（B-NOISE-02）

## 不要做的外推

| 错误用法 | 原因 |
|---|---|
| 「2 头总是更好」 | w=32 与 dff=256 时失效 |
| 「dff 越大越好，无限加」 | w=128 上收益变薄；且反例 margin 更大 |
| 「越深越好」 | 包内可双峰 |
| 「Transformer 必胜 GRU」 | 中高 lr 下反例很大 |
| 把 E8 胜率加成线性总分 | 交互存在；自测已证明会错 |
| 跨 V 搬绝对 CE | B-DIFF-01 |
