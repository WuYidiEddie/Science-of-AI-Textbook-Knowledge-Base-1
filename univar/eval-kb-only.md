# 知识库单独做题评测（univar）

## 问题

只使用 `knowledge_base/univar` 的 C01–C08（不查 measured/source 原始行、不补训练），能否做对 `experiments/univar/questions.jsonl` 的 100 道题？

## 方法

把 C03（更深/更宽）、C04（更多 LN）、C05（残差×LN，且**只在 C05 适用范围内启用**）、C06（步数/优化器/lr）写成打分器，对每题 3 个选项预测优劣，取最高者。  
打分器脚本在 `experiments/univar/eval_kb_only*.py`（不进本目录）；本目录只保留结论。

三版规则：

| 版本 | 说明 |
|---|---|
| v1 | 加性打分；C05 残差交互按原文全局使用 |
| v2 | 同上，但 C05 仅在探针支持集（relu/silu × d∈{1,3,5} × w∈{32,128}）内启用；强化 3e-5 惩罚 |
| vote | 两两多数投票（KB 因子谁好谁得票），平局用连续分 |

## 结果

| 题型 | n | v1 | v2 | vote | 随机 |
|---|---:|---:|---:|---:|---:|
| architecture_only | 34 | **23/34 = 67.6%** | 24/34 = 70.6% | 23/34 = 67.6% | 33% |
| optimizer_only | 33 | **25/33 = 75.8%** | 24/33 = 72.7% | 24/33 = 72.7% | 33% |
| mixed | 33 | **25/33 = 75.8%** | 23/33 = 69.7% | 23/33 = 69.7% | 33% |
| **合计** | **100** | **73/100 = 73%** | 71/100 = 71% | 70/100 = 70% | 33% |

对照：用题对齐实测 mean-MSE argmin 是 **99/100**（C01）。  
**结论：知识库能把正确率从 33% 提到约 73%，但单靠规则做不到高精度；刀刃局必须靠测量。**

## 分题型解读

### optimizer_only — 约 73–76%

C06 的「步数越多越好、3e-5 系统性偏差、Adam/AdamW 长预算占优」能抓住多数题。  
失手集中在：

1. **银行排序 ≠ 单题定理**：如 `q_9e733e` 在题面 2048 步下 Adagrad 优于 Adam，而 C06 的 e9b 均值写的是 Adam 更好。
2. **SGD + momentum/wd 的边界**：C06 只写了「带 momentum 的 SGD 不必总差」，没有可操作的因子权重。
3. **3e-5 惩罚过头成硬淘汰**（pack-01 kb1-2 反例）：`q_54b1cf`（RMSprop@3e-5+好架构 胜 SGD@3e-4）、`q_f2207b`（AdamW@3e-5 胜 SGD@3e-3）说明 3e-5 只能当强负项加权，**不能见 3e-5 直接判死**。详见 C06 文末「做题警示」。

### mixed — 约 70–76%

先被优化器/步数拉开的题好做；当三选项训练语境接近、只差架构时，退化为 architecture_only 难度。

### architecture_only — 约 68–71%（短板）

与 spiral 的 kb-only（架构题 53%）、本项目 coverage 的架构 argmax（约 53%）同量级：**纯架构比较是刀刃局**。

规则冲突例子（说明 C03/C04 不能无脑加权）：

- `q_2e3336`：官方选 **无 LN** 的 B，同 depth 同 width——与 C04「更多 LN 更好」相反（C04 也有 91:5 之外的例外）。
- `q_f9ff79`：官方选 d=2 + 1 个 LN + wider，而不是更深的 C——深度与 LN/宽度权重需按题面语境再平衡。
- `q_11180c` / `q_e576c7`：间隔极小（C07 刀刃），规则无法稳定分辨。

## 这次评测暴露的 KB 缺口

| 缺口 | 现状 | 影响 |
|---|---|---|
| LN **位置**（而不仅是数量） | C04 明确写「证据不足」 | 架构题失手 |
| 残差规则的**完整适用边界** | C05 只覆盖 Adam×relu/silu×d1/3/5×w32/128 | v1 全局套用会错，v2 收紧后别的题又缺规则 |
| 优化器 **×lr ×steps 交互** | C06 给的是银行均值 | 个别 optimizer 题被均值误导 |
| **权重/强度**只有方向没有标定 | C03/C04 只给胜率 | 加性打分只能猜相对系数 |
| 刀刃题的**拒判/低置信** | C07 只描述噪声 | 仍会硬选 |

## 范围与限制

- 只评 univar 100 题；打分器是 C01–C08 的一种实现，不是唯一实现（v1/v2/vote 差 2–3 题）。
- **没有**使用 `questions` 外的实验行；若允许查 measured 题对齐结果，可达 99%（C01）。
- 答案以 `questions.jsonl` 的 `answer` 为准。
- 「73%」是规则系统的做题能力，不是知识库「错误率」：知识库陈述的受控结论（更深/更宽/更多 LN/步数）本身在适用范围内仍然成立。

## 可改进方向（超出「只用 KB」）

1. 为 architecture_only 补 **题面语境内的** 架构排序表或因子强度标定。
2. 把 C05 写成显式条件规则（条件 + 方向 + 强度），而不是散文交互。
3. C06 补「长预算下 Adagrad 可反超」的边界实例。
4. 刀刃题输出低置信，不强行 argmax（与 C07 一致）。
